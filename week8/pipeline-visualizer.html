Pipeline visualizer

Step short instruction sequences through a five-stage pipeline, switch forwarding on and off, and count the cycles that hazards cost.

How to use this interactive
  1. Pick a short RISC-V sequence. Each colored block in the 3D view is one instruction waiting in program memory on the left.
  2. Press Step to advance one clock cycle. Every block moves one stage to the right: fetch (IF), decode (ID), execute (EX), memory (MEM), and write back (WB). The caption explains what happens in each stage.
  3. Watch for red blocks: an instruction that needs a result that is not ready yet must wait (a stall), and a gray bubble moves through the pipeline in its place.
  4. Turn forwarding on and run the same sequence again. Orange arcs show results passed straight from one stage to the next, and many stalls disappear.
  5. Compare the cycle counts with and without pipelining, then try the quick check at the bottom.

    The laundry analogy

    Washing, drying, folding, and putting away one load takes four steps. You do not wait for a load to be put away before starting the next wash: while load 1 dries, load 2 washes. Each load still takes the same time, but a new load finishes at every step. A processor pipeline does the same with instructions.

    A hazard is anything that stops the next instruction from starting on time. Here you see data hazards: an instruction needs a value that an earlier instruction has not produced yet.
