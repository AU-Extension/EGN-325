    The laundry analogy

    Washing, drying, folding, and putting away one load takes four steps. You do not wait for a load to be put away before starting the next wash: while load 1 dries, load 2 washes. Each load still takes the same time, but a new load finishes at every step. A processor pipeline does the same with instructions.

    A hazard is anything that stops the next instruction from starting on time. Here you see data hazards: an instruction needs a value that an earlier instruction has not produced yet.

    Things to notice

    • Once the pipeline is full, one instruction finishes every cycle, even though each one still passes through all five stages.
    • Without forwarding, a value is only readable in ID during the cycle its producer is in WB, so a dependent instruction right behind it waits two cycles.
    • Forwarding sends an ALU result straight from MEM or WB into EX, so most stalls disappear.
    • A load has its value only after MEM, so the instruction right after a load still waits one cycle, even with forwarding.
    How to use this interactive
    1. Pick a short RISC-V sequence. Each colored packet on the board is one instruction, starting in program memory on the left.
    2. Press Step to advance one clock cycle. Every instruction moves one stage to the right: fetch (IF), decode (ID), execute (EX), memory (MEM), and write back (WB). The narration explains what happens in each stage.
    3. Watch for red: an instruction that needs a result that is not ready yet must wait (a stall), and a bubble moves through the pipeline in its place.
    4. Turn forwarding on and run the same sequence again. Orange packets show results passed straight from one stage to the next, and many stalls disappear.
    5. Turn on Predict before you see it to say where an instruction will be in the next cycle before each step.
    6. Compare the cycle counts with and without pipelining, then try the quick check at the bottom.
